# گزارش وضعیت سامانه بنکداری هوشمند — نسخه فعلی

> تاریخ به‌روزرسانی: ۱۴۰۵/۰۹/۰۱ (۲۰۲۶-۱۱-۲۲)
> این سند گزارش صادقانه درصد تکمیل ماژول‌ها، نتایج واقعی تست‌ها و نقشه راه ادامه است.

## ۱) معماری پیاده‌سازی‌شده

- **Frontend:** Next.js 16 (App Router) + TypeScript + Tailwind CSS 4 + shadcn/ui + Recharts — تک‌صفحه‌ای (SPA) در مسیر `/` با ناوبری hash؛ فارسی، RTL کامل، فونت Vazirmatn، تاریخ شمسی با `Intl`، اعداد فارسی، مبالغ با تبدیل ریال→تومان در UI.
- **Backend:** Route Handlers زیر `/api/*` با قالب پاسخ یکپارچه `{ ok, data }` / `{ ok, error:{code,message} }`، اعتبارسنجی Zod، Rate Limiting مقدماتی در حافظه، Audit Log روی عملیات حساس.
- **Database:** SQLite + Prisma (محیط توسعه/دمو). مبالغ مالی به‌صورت **Integer ریال**؛ مقادیر انبار **Integer واحد پایه**. مسیر مهاجرت به PostgreSQL + Hyperdrive در فاز استقرار مستند شده است (بخش ۶).
- **حساب‌ها و دسترسی‌ها:** احراز هویت با شماره موبایل + رمز (scrypt + salt)، نشست با توکن تصادفی و Hash SHA-256 در DB، کوکی HttpOnly، لغو نشست هنگام غیرفعال‌سازی/تغییر رمز، RBAC کامل با ۱۰ نقش و ۲۹ مجوز — کنترل در **سرور**، نه فقط UI.
- **موتور موجودی:** رزرو اتمیک با `UPDATE` شرطی داخل `Transaction` (ضد Overselling)، آزادسازی کنترل‌شده، خروج فیزیکی با **FEFO**، ورود کالا با لات/بچ/انقضا، تعدیل با دلیل، Ledger کامل حرکات.
- **ماشین حالت سفارش:** `SUBMITTED → RESERVED → CONFIRMED → CREDIT_APPROVED/PAID → PICKING → READY_FOR_DISPATCH → DISPATCHED → DELIVERED → COMPLETED` + مسیرهای `REJECTED`/`CANCELLED` با آزادسازی رزرو و سند اصلاحی مالی.
- **موتور قیمت‌گذاری:** سمت سرور؛ اولویت `CUSTOMER > GROUP > TERRITORY > VOLUME > DEFAULT`؛ پنجره زمانی و محدوده مقدار؛ خطای صریح `AMBIGUOUS_PRICE_RULES` در تساوی ناسازگار؛ Snapshot کامل قیمت در `OrderItem` تا تغییر قیمت آتی، فاکتورهای گذشته را تغییر ندهد.
- **مالی:** دفتر مشتری و تأمین‌کننده (Ledger-based)، فاکتور در لحظه تحویل، دریافت/پرداخت با سند منفی، سند اعتبار (CREDIT_NOTE) مرجوعی، عدم حذف مخرب اسناد.
- **Idempotency:** کلید یکتا در ثبت سفارش — ارسال مجدد در قطع اینترنت، سفارش تکراری نمی‌سازد (تست شده).
- **اعلان‌ها:** رویدادمحور در DB (سفارش جدید، وضعیت، کم‌موجودی، مرجوعی، پیام) + Polling سبک در UI.
- **پیام‌رسانی:** گفت‌وگوی خصوصی ذخیره‌شده در DB با اعلان؛ نسخه اول با Polling (ارتقای WebSocket/Durable Objects در استقرار Cloudflare پیش‌بینی شده است).

## ۳) نتایج واقعی تست‌ها (scripts/smoke.sh — ۳۶/۳۶ PASS)

**سناریوهای حیاتی سند پروژه:**
- ✅ سناریو ۱ (ضد Overselling): دو سفارش هم‌زمان از موجودی محدود → دقیقاً یکی رزرو قطعی می‌شود، دیگری `INSUFFICIENT_STOCK 409`
- ✅ سناریو ۲ (رزرو ≠ خروج فیزیکی): ثبت سفارش فقط Reserved را کم می‌کند؛ Physical تنها در `deliver` با FEFO کاهش یافت (۱۰۰ → ۵۲ پایه)
- ✅ سناریو ۳ (درخواست تکراری): ارسال مجدد با همان Idempotency Key → `idempotent:true`، سفارش تکراری ساخته نشد
- ✅ سناریو ۴ (لغو): لغو سفارش → رزرو آزاد شد و Available به ۱۰۰ بازگشت
- ✅ سناریو ۵ (قیمت اختصاصی): قیمت CUSTOMER مشتری کاوه (۲٬۱۰۰٬۰۰۰) بر DEFAULT (۲٬۲۰۰٬۰۰۰) مقدم بود
- ✅ سناریو ۶ (انقضا): لات‌های منقضی در UI و API تفکیک و از مسیر عادی فروش خارج‌اند (FEFO اولویت بچ زودترمنقضی)
- ✅ سناریو ۷ (مرجوعی): درخواست روی سفارش تحویل‌شده، QC با RESTOCK → ورود ۲۴ پایه به انبار + سند اعتبار در Ledger
- ✅ سناریو ۸ (دسترسی): ویزیتور به `/api/finance` و `/api/users` دسترسی ندارد (403) اما می‌تواند سفارش ثبت کند
- ✅ سقف اعتبار: سفارش اعتباری مازاد بر سقف → `CREDIT_EXCEEDED 402`
- ✅ ورود اشتباه → `BAD_CREDENTIALS 401` + ثبت Audit با نتیجه DENIED

**راستی‌آزمایی مرورگر (Agent Browser):** ورود مدیر، داشبورد با داده واقعی، لیست/جزئیات سفارش با Timeline، ثبت سفارش کامل از UI با پیش‌نمایش قیمت زنده سرور، انبار (موجودی/لات‌ها/گردش)، گزارش‌ها، کاربران/ماتریس دسترسی، اپ ویزیتور موبایل با کارنامه — بدون خطای کنسول؛ چیدمان RTL/فونت/اعداد فارسی در دسکتاپ و موبایل تأیید شد.

## ۴) محدودیت‌های شناخته‌شده (صادقانه)

1. **Runtime:** این نسخه روی Sandbox اجرا می‌شود (SQLite). استقرار واقعی Cloudflare Workers/Hyperdrive/R2/Queues انجام **نشده** — ادعای استقرار نمی‌شود؛ پیکربندی موردنیاز در بخش ۶ مستند است.
2. **پرداخت آنلاین و SMS:** Adapter طراحی شده ولی اتصال واقعی به درگاه/سرویس پیامک ایرانی نیازمند اعتبارنامه‌های واقعی است.
3. **پیام‌رسانی Real-time:** فعلاً Polling؛ در استقرار، Durable Objects + WebSocket Hibernation جایگزین می‌شود.
4. **نقشه تعاملی مناطق:** Leaflet هنوز اضافه نشده؛ داده GIS فقط از ورود رسمی مدیر پذیرفته می‌شود (بدون حدس).
5. **E2E با Playwright:** سناریوهای E2E فعلاً با Agent Browser به‌صورت دستی اجرا شد؛ خودکارسازی Playwright در فاز QA.
6. **حذف داده DEMO:** کاتالوگ/قیمت‌ها/موجودی اولیه با پرچم `isDemo` (DEMO_SEED) هستند و مدیر می‌تواند اصلاح/غیرفعال کند.

## ۵) نقشه راه ادامه (بازنویسی فازها بر اساس وضعیت فعلی)

- **فاز A — استقرار Cloudflare:** انتقال به PostgreSQL + Hyperdrive (Drizzle یا Prisma+driverPlanetScale معادل)، OpenNext Adapter، R2 برای تصاویر کاتالوگ (Presigned URL)، Queues برای اعلان‌ها، Durable Objects برای چت، Cron برای انقضا/سررسید، Secrets امن، Health Check و Deploy Script.
- **فاز B — خرید و تأمین:** درخواست/سفارش خرید رسمی، فاکتور خرید، هزینه‌های جانبی، سند مالی خرید، بهای تمام‌شده واقعی لات از فاکتور خرید.
- **فاز C — PWA ویزیتور:** صف آفلاین سفارش با همگام‌سازی و تأیید سرور.
- **فاز D — پورسانت کامل:** قوانین درصدی/وصولی/پلکانی با Snapshot و رویداد معکوس هنگام مرجوعی.
- **فاز E — نقشه Leaflet:** ترسیم Polygon مدیر، اعتبارسنجی هم‌پوشانی، نسخه‌بندی مناطق.
- **فاز F — حسابداری رسمی:** دفاتر روزنامه/کل، دوره مالی، تراز آزمایشی.
- **فاز G — QA خودکار:** Playwright E2E + تست‌های هم‌زمانی، Security Review نهایی.

## ۶) راهنمای اجرای محلی و استقرار

**اجراهای پرکاربرد:**
```bash
bun run dev                 # سرور توسعه (پورت 3000)
bun run lint                # ESLint
bun run db:push             # اعمال اسکیما
bun run scripts/seed.ts     # Seed اولیه Idempotent (رمزها از .env)
bun run scripts/reset-data.ts  # بازنشانی منطقی داده‌ها (بدون حذف فایل DB)
bash scripts/smoke.sh       # تست دود کامل — ۳۶ چک
```

**حساب‌های نمایشی این محیط:** مدیر `09120000000 / Admin#1404` — ویزیتور `09120000005 / Demo#1404` — سایر نقش‌ها `09120000001..9 / Demo#1404`. در Production این رمزها **باید** تغییر کنند (متغیرهای `ADMIN_PASSWORD` و `DEMO_USERS_PASSWORD`).

**چک‌لیست استقرار Cloudflare (فاز A):**
1. انتقال اسکیما به PostgreSQL؛ اجرای Migrationها؛ اتصال با Hyperdrive.
2. `@opennextjs/cloudflare` + Wrangler + `nodejs_compat` + compatibility date معتبر.
3. R2: آپلود تصاویر کاتالوگ با Presigned URL و URLهای CDN.
4. Queues: پردازش اعلان/SMS؛ Cron: هشدار انقضا و سررسید.
5. Durable Objects: چت بلادرنگ (WebSocket Hibernation).
6. Secrets از طریق `wrangler secret put` — هیچ Secretی در مخزن قرار نمی‌گیرد.
7. Health Check `/api` و Runbook عملیاتی.
